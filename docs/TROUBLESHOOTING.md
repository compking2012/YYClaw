# Troubleshooting and Quality Checks

This is a development-only companion to the PRD, feature breakdown, and architecture. It records environment traps and quality gates, not public feature claims. See [DOCUMENTATION.md](DOCUMENTATION.md) for the document hierarchy.

- **Autonomous development**: `pnpm harness autopilot` requires clean committed inputs matching the remote target SHA, an authenticated compatible Codex CLI, authenticated `gh`, Git push rights and a green baseline. A failed baseline blocks coding. Publication, missing CI, unverified process ownership, stale evidence or cleanup failures leave explicit non-success run states under `artifacts/autopilot/`; inspect `run.json` before `resume --run <id>`. Resume keeps the original deadline. Never delete retained foreign/unbacked resources merely to turn a run green.
- **Autopilot frozen input errors**: Changed files, a stale plan, an unpublished target branch and a task-count budget mismatch are separate failures. Read the reported paths/counts and plan/HEAD/remote SHAs. Commit and publish only reviewed baseline fixes, then generate a new plan from the synchronized clean input. The controller neither commits user edits nor changes an old plan's `baseSha`.

## Environment and Development

- **False Codex capability errors**: Preflight resolves the launch PATH executable once and asks its parser to accept the exact exec options with `--help`. It does not search stdout help prose or invoke the model. Brief help, stderr output and a later PATH change cannot falsely remove `--json`; genuinely unsupported arguments or process failures report the selected absolute executable and fail before coding. A desktop-bundled Codex and an interactive-shell Codex may differ, so inspect the executable reported in the error.

- **UI evidence is mandatory**: Autopilot obtains fresh Playwright JSON reports for direct checks and registered E2E/performance scripts. A successful process exit cannot pass an absent, malformed, empty, failed or flaky report. Directed and acceptance-mapped UI checks reject skipped tests even if labeled quality; only controller-added whole-suite quality runs retain platform exclusions without certifying a requirement. README capture must reload after host fixtures and wait for the loaded ACP session before seeding events.
- **Git lifecycle integration timing**: The real multi-worktree CI-repair regression uses a bounded 30-second test timeout rather than Vitest’s 5-second unit default. Full Electron and unit suites should run serially on constrained hosts. This changes only the integration fixture time allowance, not assertions, autonomous command deadlines, repair budgets or acceptance requirements.

- **Isolated Autopilot baseline**: Fixtures must not use personal OpenClaw settings. Provider delivery tests mock the voice configuration boundary, and controlled pnpm fixtures declare their own `pnpm-workspace.yaml`; otherwise a TMPDIR inside a worktree can make pnpm write the outer lockfile. Resource leases publish complete JSON atomically and serialize dead-owner recovery. Unknown/corrupt leases and interrupted recovery ownership remain fail-closed for manual verification. Validate with a private HOME/TMPDIR, not only the primary user environment.
- **Current Electron regression contracts**: Install host fixtures after Main initialization and reload before exercising startup-derived stores. Do not restore retired routes to satisfy old selectors: conversation agent/channel labels select Chat, while agent model badges open provider settings; Usage is a separate settings tab and historical models remain visible. Dictation uses `voice.configStatus` and `voice.transcribe`, not the legacy ASR configuration gate. Wait for actual audio frames and confirmed settings persistence. Closing-dialog assertions must pause the real exit animation before reading it, not depend on catching a sub-100ms window.
- **Native dependency and socket isolation**: Autopilot sets `SHARP_IGNORE_GLOBAL_LIBVIPS=1` to use the locked prebuilt sharp module instead of discovering developer Homebrew/libvips and triggering fresh Homebrew downloads in each private HOME. Lifecycle scripts still execute; native PNG processing is regression-tested. POSIX CUA integration uses an owned short socket directory because deep worktree paths can exceed Unix socket limits and surface as `EADDRINUSE` even without an actual conflicting server.
- **Portaled modal focus**: Suppress outer Radix document focus traps at the body boundary, after React's portal listener receives focus/blur. Stopping events on the portal element suppresses React handlers too, so typing can work while opt-in App Secret auto-paste silently fails.

- **Baseline repair rollout**: Reviewed fixes must be committed and pushed to the target branch before generating a new plan. Never edit a frozen `baseSha`, automatically stash user changes or refresh an expired deadline. Local tests and local provider connectivity do not certify real GitHub/three-platform acceptance.

- **Autopilot missing planning rules**: `Task ... must retain the docs-sync contract` means the proposal omitted mandatory documentation review, not that the model connection or dependency install failed. The controller completes universal and UI/comms-tag-mandated rules before freezing newly generated proposals and records additions under `planning/rule-additions.json`. Test-only tasks must review documentation impact but need not write unrelated docs. Existing frozen plans are still validated strictly and are not auto-edited; unsafe paths, unknown rules and missing acceptance remain errors.

- **Autopilot uv postinstall failures**: Exit code 1 after successful package installation can come from `pnpm run uv:download`, not the model or sharp. The controller verifies the primary project's native uv against the frozen workspace's required version and copies it through `node_modules/.autopilot-cache/releases/installed-uv/` into each task. Architecture, actual `--version` and receipt hashes must match; missing/corrupt/wrong-version binaries retain official downloads. A version marker alone is insufficient. Nested lifecycle pnpm commands reuse the controller CLI without a fresh Corepack download. Unavailable official GitHub assets explicitly block initialization with their URL and proxy guidance; cc-switch model connectivity does not establish GitHub release connectivity.

- **Autopilot dependency timeouts**: Inspect the run's `baseline/install.log` and `initialization.json` before blaming the model connection. Shared pnpm/download cache paths are persisted in `run.json`; every workspace uses the dedicated cache under the primary project's `node_modules/.autopilot-cache/`, copies its own dependencies and downloads only missing versions. Existing installed packages are not a pnpm content store; first use may still need cache warmup. Resume relocates legacy external cache metadata without deleting old stores or changing frozen inputs. Proxy/certificate/mirror settings enter dependency initialization, but private npm/publisher/model credentials do not. Missing private-package access is an environment blocker. `--init-timeout-minutes` defaults to 30; model/tests retain 20-minute command limits, all capped by the original run deadline. Stage/log heartbeats occur every minute. A lifecycle failure is not automatically a download failure or coding defect. Caches survive failed-task cleanup; manually removing the primary `node_modules` removes them, so never do that during a run. Expired runs require a newly generated plan from current committed inputs; do not edit a frozen plan's base SHA. Host-resource and initialization leases use atomic publication and exclusive dead-owner recovery; unknown ownership requires manual verification rather than unsafe deletion.

- **Autopilot with cc-switch**: Planning, coding and review inherit the local Codex model/provider connection from `$CODEX_HOME/config.toml` (default `~/.codex/config.toml`), including authentication and proxy/certificate variables. Keep cc-switch running when the provider uses its local endpoint. `--model` changes the model only. A private filtered config/auth copy is deleted with the task HOME; user hooks, MCP servers, plugins, trust settings and publishing credentials are not inherited. Missing providers or required keys fail explicitly. Older adapters used `--ignore-user-config` and could unexpectedly select the default OpenAI provider; a timeout from that route did not mean the configured cc-switch connection was failing. Inspect configuration locally without posting credentials or complete config/auth files in logs.

- **Bundled download timeouts**: uv and agent-browser downloads retry failed requests,
  then fall back to system curl. If GitHub is unreachable, set `HTTPS_PROXY` to
  your actual HTTP proxy address before `pnpm run init`. Fetch does not accept SOCKS
  proxy URLs. Downloads continue to use official GitHub releases, not mirrors.
- **Package manager is `pnpm` only** — never `npm`/`yarn`. The exact version is pinned
  via the `packageManager` field in `package.json`.
- **Before declaring a change done**, run the relevant checks (or just run `/check`):
  `pnpm lint` · `pnpm typecheck` · `pnpm test`.
- **Renderer/Main boundary is enforced by ESLint** — never add a direct
  `window.electron.ipcRenderer.invoke(...)` call or a renderer→`localhost`/`127.0.0.1`
  `fetch(...)`. Route everything through `src/lib/host-api.ts` and
  `src/lib/host-api-client.ts`. (Full rationale in AGENTS.md.)
- **Non-mutating lint baseline**: CI and autonomous development use `pnpm run lint:check`.
  Generated `artifacts/` (including temporary worktrees), `test-results/`, and
  `playwright-report/` are excluded; repository source rules remain enforced.
  Previously unapproved blanket TypeScript suppression directives are removed, so run typecheck
  alongside lint. Explicit-`any` warnings remain advisory, not a reason to bypass errors.
- **Autopilot worker `listen/spawn EPERM`**: If the committed baseline passed but a coding worker cannot run loopback servers or child-process integration tests, inspect the worker's `coding/events.jsonl`; this is a worker sandbox restriction, not proof that controller tests failed. Code-ready workers return `validation-pending`; the controller runs all frozen checks in the same owned worktree and read-only review inspects the actual reports. Do not broaden Codex permissions, skip tests or treat worker assertions as acceptance. Genuine missing requirements, external conditions, unauthorized writes and controller failures still block delivery. Existing blocked records are preserved and never reinterpreted by matching error text; after reviewed fixes are committed/pushed, generate a fresh plan rather than edit its base SHA. Deferred status does not certify F33 external or cross-platform delivery.
- **Duplicate review verdicts**: Independent review must return exactly one passing verdict per frozen acceptance ID. A duplicate appended to an otherwise complete set fails acceptance even when all local commands pass. Inspect `acceptance.json`; do not delete criteria or edit evidence to pass. The frozen-contract regression covers this fail-closed boundary with controlled evidence, not real external-account certification.
- **Autopilot startup versus write scope**: An isolated coding worker must read the controller's `initialization.json` instead of rerunning broad `pnpm run init` outside its frozen write paths. The AGENTS controller-owned startup rule requires same-task/resource/base-SHA evidence of lifecycle installation, bridge generation and startup typecheck, all exiting 0. Missing, failed or changed evidence blocks coding. This receipt does not certify optional bundled tools or replace task acceptance; manual setup remains unchanged.
- **Autopilot stack integration timing**: The disposable-Git test that publishes two task branches and verifies cleanup before CI has a scoped 30-second allowance, matching the existing stack-repair test. Its real worktree, archive, commit, push, and cleanup operations can exceed Vitest's five-second default during a full parallel unit run. Premature test termination also lets unfinished writes race fixture teardown (`ENOTEMPTY`). Keep all publication, ownership, clean-worktree, and current-SHA assertions; this is not a change to runtime command limits, acceptance gates, or the global unit-test timeout.
- **UI changes** must add or update a Playwright E2E spec in the same change — run `/e2e`.
- **Comms-path changes** (gateway events, runtime send/receive, delivery, fallback)
  must pass `/comms-check` before finishing.
- **Doc-sync**: when behavior, flows, or interfaces change, update `README.md`,
  `README.zh-CN.md`, `README.ja-JP.md`, and `README.ru-RU.md`, plus the matching localized guides, for implemented behavior. Requirements and target-only design changes belong in root development docs and harness, not introductions.
- **Merging `upstream/main`**: this is a customized fork — preserve fork
  customizations by default and only take upstream content for a feature/fix/compat
  reason. Follow `harness/specs/rules/upstream-merge.md` before resolving conflicts.
  - **Electron dev binary arch (macOS)**: `package.json`'s `pnpm.supportedArchitectures.cpu: ["x64","arm64"]` (kept so `release:mac` can package both Intel and Apple Silicon) makes pnpm run electron's install script twice; both arches extract into the same `node_modules/electron/dist`, racing — on Apple Silicon this often leaves an x86_64 (Rosetta, slow under `pnpm dev`) or half-extracted dist. `postinstall` runs `scripts/fix-electron-dev-arch.mjs` to realign that dist to the host-native arch (idempotent, uses the `@electron/get` cache). This dist is dev-only; `release:mac` is unaffected because electron-builder downloads its own Electron per target arch. If `pnpm dev` ever errors with *"Electron failed to install correctly"*, just re-run `node scripts/fix-electron-dev-arch.mjs`.
- **Provider API payload naming**: Remote provider API payloads should only map `camelCase` fields (e.g. `p.defaultApiKey`, `p.defaultBaseUrl`). Do not add fallback checks for `snake_case` versions.
- **Persisted redaction placeholders**: If startup reports `Cannot save redacted OpenClaw credentials`, the error identifies the affected field. Retain a private backup of the damaged config and restore only matching credential values from a verified local backup, or re-enter them. Do not delete channels, replace the full current configuration, or disable validation. Invalid placeholder errors are not repaired by reconnecting.
- **Development startup integrations**: Development launches do not check release updates or register macOS login items. `dev-app-update.yml` is not required for `pnpm dev`; packaged update checks and login-item behavior remain enabled.
