# YYClaw の機能

## 製品ビジョンと目標範囲

YYClaw は、プライバシーとコストを制御でき、信頼性・拡張性・監査可能性を備えた、**オープンソースでベンダーに依存しないクロスプラットフォーム AI ワークベンチ**を目指します。共通 Agent ランタイムがデスクトップ、携帯コンソール、利用者所有の Linux 常時稼働サーバーを結びます。六つの柱は MIT とモデルの中立性、権限に応じた一貫した体験、ローカル・クラウド連携、マルチモーダル処理、決定的で監査可能な自動化、グローバルと中国のエコシステムです。

開発者のコード・運用、クリエイターの非公開素材・定時配信、小規模チームの IM・顧客対応、研究教育の機密分析・文献処理を想定します。画面・音声・文書・動画の理解、テキスト・グラフ・画像・音声・動画脚本、XState の明示的な推論ノードと再試行・承認・復旧、Agent 分離、追跡可能な Cron、クラウド／ローカルモデル、MCP、国際ツールと Feishu/Lark・DingTalk・WeCom が目標です。

**製品目標であり、すべて提供済みではありません。** モバイル、リモート管理、同期、配置、移行は目標要件です。機密タスクとローカル操作は端末に残します。ローカル Agent がクラウドモデルを呼ぶ場合、端末内完結とは言えません。[完全な PRD](../PRODUCT.md) と [提供状況](../FEATURELIST.md) を参照してください。以下は現在のデスクトップ機能です。

スローガン候補：*One Workbench, All Devices, Any Model.* — ひとつのワークベンチ、あらゆるデバイス、あらゆるモデル。

開発者モード限定の独立した画像生成サイドバーページを維持します。ローカルの開発者設定と統合済みの上流エンドポイント設定を共有し、モデル管理は従来の設定ダイアログに残します。

ローカルプロバイダーカタログに TokenDance のブラウザー認証と API キー設定を追加し、上流の中国語での表示ルールとリクエスト識別を維持します。Anthropic と Google には上流の接続設定を追加します。既存のモデル ID、既定値、複数モデルの能力スロット、およびリモート・ローカルの選択と開発者用フォールバックは変更しません。

このドキュメントは [README](../../README.ja-JP.md) の「機能」セクションの詳細版です。
README に載せるには細かすぎる実装上の注意点、制限、設定の仕組みをここにまとめています。


### 上流機能の統合

入力欄はローカルのアカウント名と会話限定のモデル選択を維持します。ACP コンテキスト使用量は Gateway 状態の左に表示され、新しいランタイム情報を優先します。圧縮状態とネイティブ子エージェントの読み取り専用表示は独立したワークフロー表示と共存します。`@agent` は対象エージェントの新しい会話を開始します。

圧縮予約はグローバルな既定の会話モデル変更時だけ再計算します。明示された上限の25%、上限がなければ50,000トークンです。エージェント別指定、メディア枠、起動同期では再計算せず、明示された設定を保持します。

DingTalk は上流公式コネクターを使用し、複数アカウントと任意のワークスペース認証を維持します。Computer Use は上流のローカルドライバーと権限管理を使用します。設定 → バージョン情報から匿名化した診断と明示的に選択した生の会話をローカルZIPへ保存し、自動アップロードしません。

## ゼロ設定バリア

インストールから最初の AI 対話までを、直感的なグラフィカルインターフェースだけで
完了できます。ターミナルコマンド、YAML ファイル、環境変数探しは不要です。

初回起動時のウィザードは、**言語と地域**（対応していればシステム言語を事前選択、
そうでなければ英語）、**AI プロバイダー**（API キー、またはプロバイダーが対応していれば
ブラウザ／デバイス OAuth）、**スキルバンドル**、**検証**の各ステップをカバーします。
完了すると「セットアップ完了」フラグが永続化され、チャットへリダイレクトされます。
ウィザードはスキップ可能で、プロバイダーキーがなくても UI は完全に操作でき、
完了に Gateway の準備完了は必要ありません。

## インテリジェントチャットインターフェース

モダンなチャット体験で AI エージェントと対話できます。YYClaw は複数の会話コンテキストと
メッセージ履歴に対応し、アシスタントの応答はストリーミング Markdown として描画されます。
シンタックスハイライト付きのフェンスコード、CJK に配慮したパース、GitHub 風テーブル、
KaTeX による LaTeX 数式（`$inline$`、`$$block$$`、`\(inline\)`、`\[block\]`）に対応します。
ユーザー入力はそのままのテキストを保持します。メインの入力欄はマルチエージェント構成向けの
`@agent` 直接ルーティングにも対応します。フェンスコードはソースの改行を保持し、
長い行をソフトラップし、ストリーミング完了後にローカライズされたコピー操作を提供します。

入力欄から挿入したスキルは `/skill-name` カードとして表示されます。カードをクリックすると
プレビューサイドバーが開き、そのスキルの `SKILL.md` を読めます。

`@agent` で別のエージェントを指定すると、YYClaw はデフォルトエージェント経由で中継せず、
そのエージェント自身の会話コンテキストへ直接切り替えます。エージェントのワークスペースは
既定で分離されており、より強いランタイム隔離は OpenClaw のサンドボックス設定に依存します。

設定済みモデルが複数ある場合、入力欄には**モデル**ピッカーも表示されます。モデル変更は
OpenClaw のネイティブな設定ウォッチャーによって適用され、Gateway の再起動は不要です。
YYClaw はライブの `agents.list` スナップショットが選択したモデルを反映するまで待ってから、
次の送信を許可します。スキルはエージェント単位で有効になります
（`agents.list[].skills`）。エージェントの作成・編集時にそのエージェントの有効スキルを
選択でき、後方互換のため従来のグローバルなスキル切り替えは各既存エージェントへ一度だけ
移行されます。

### セッションサイドバー

セッションサイドバーはワークスペース優先です。デフォルトのワークスペースが最上部に固定され、
他のワークスペースは自然順に並び、各ワークスペースは折りたたみやセッションの追加読み込みが
できます。セッション行は AI が応答中はスピナー、未読の応答が完了すると青いドット、
会話を開いた後は相対的な活動時刻を表示します。ホバーすると行のアクションが現れます。
インポートしたワークスペースはサイドバーのヘッダーから名前を変更できます。カスタム名は
チャット入力欄に反映され、ヘッダーにホバーするとファイルシステム上のパスが表示されます。

有効なワークスペースが選択されている場合、新しいチャットはそれを継承し、最初の送信まで
編集可能なままです。編集可能な新規チャットや未バインドのチャットには、入力欄に
ワークスペースチップが表示されます。そのメニューには最近使用したワークスペースと既知の
セッションのワークスペースが並び、デフォルトのワークスペースへ戻ることも、別のフォルダーを
選ぶこともできます。保存済みのワークスペースフォルダーが移動または削除されていた場合、
チャットはセッション作成を一時停止し、存在しないパスを繰り返し再試行するのではなく、
既存のフォルダーを選ぶよう促します。利用できない非デフォルトのグループはサイドバーで
マークされ、確認後に削除できます。これはそのグループ内のすべてのセッションを恒久的に
削除します。セッション行が消え、ナビゲーションが変わるのは恒久的な削除が成功した後だけで、
削除が失敗した場合は再試行できるよう会話と確認ダイアログが残ります。

OpenClaw が合成した UUID と日付のフォールバックタイトルは、それがセッション ID と一致する
場合にのみ「欠落」として扱われ、その後セッション名として永続化される代わりに会話の最初の
ユーザープロンプトで置き換えられます。

コールドスタート後、または Gateway 再起動後、特定の会話をまだ開いていない場合、チャットは
最後に更新されたセッションを復活させるのではなく、まったく新しい空の会話に着地します。
既存のセッションはサイドバーに残ります。

### ドキュメントプレビュー

チャット右パネルの「ワークスペース」と「プレビュー」タブは、Markdown、`.docx`、`.pptx`
ファイルの読み取り専用プレビューを提供します。Markdown プレビューは静的レンダリング
モードでも、シンタックスハイライト、ソフトラップ、コピー可能なフェンスコード、CJK に
配慮したパース、KaTeX 数式に対応します。プレビューヘッダーは選択したファイルを YYClaw の
ビューポート全体に拡大できます。同じコントロールか Escape でパネルに戻れます。

制限：旧形式の `.doc` と `.ppt` はインラインではなく OS 経由で開きます。DOCX のページ
区切りは Microsoft Word と異なる場合があります。PPTX プレビューはアニメーション、
画面切り替え、メディア再生に非対応です。20 MB を超える Office ファイルはインラインで
プレビューされません。

## ローカル HTML プレビュー

チャット右パネルには「ワークスペース」「プレビュー」「変更」タブがあります。汎用の
ウェブブラウザー、ホームページ、アドレスバーは提供しません。許可されたローカルの `.html`
および `.htm` の添付ファイル、ファイルアクティビティ、ワークスペースのファイルは既定で
プレビューで開きます。ファイル操作では内蔵プレビューかシステムアプリケーションを選べ、
プレビューヘッダーからは現在の HTML ファイルをシステムブラウザーで開けます。

すべてのリンクはクリックできません。YYClaw が描画するリンクは通常のテキストとして表示され、
HTML プレビュー内のリンクはスタイルとポインター操作が取り除かれます。HTML プレビューは
フォーム、スクリプトによるナビゲーション、リダイレクト、ハッシュナビゲーション、ポップ
アップ、ダウンロード、ネットワークリクエスト、デバイス権限もブロックします。自己完結型の
ローカル HTML は描画できますが、選択したドキュメントから出ることはできません。

## 音声対話

エージェントに話しかけ、その応答を聞けます。音声は OpenClaw カーネルのネイティブな
Talk/TTS Gateway RPC 経由で完結し、追加サービスは不要です。

- **音声入力**は OpenClaw の **Talk モード**を使います。*ディクテーション*
  （プッシュトゥトーク）は音声を入力欄に書き起こし、送信前に確認できます。*会話*モードは
  継続的なハンズフリー対話（聞く → 考える → 話す）を開き、サーバー側の音声活動検出と
  割り込みに対応します。モードは **設定 → 音声** で切り替えます。
- **音声出力（TTS）**：各アシスタント応答に 🔊 再生ボタンがあり、
  **設定 → 音声 → 自動読み上げ**で最終応答を自動的に読み上げられます。
- マイクへのアクセスは初回使用時に確認されます。macOS ではアプリがシステムのマイク権限を
  要求します。

### 音声モデルの設定

音声モデルは**モデル**ページでチャットプロバイダーと並んで一覧表示されます。プロバイダー
定義はリモートのプロバイダーカタログに到達できればそこから、できなければ同梱の
`resources/config/providers.json` から読み込まれます（両者はどちらか一方で、マージは
されません）。したがって、どの機能タイプ（`tts` / `transcription` / `realtime` を含む）が
提供されるかはその取得元に依存します。

プロバイダーの API キー、モデル、ベース URL を設定します。選択内容は OpenClaw の設定
（`messages.tts` と `voice-call` プラグイン）に書き込まれます。本リリースは 2 つの内蔵
音声ランタイム、**OpenAI** と **MiniMax** に対応し、プロバイダーの
`voiceRuntimeProviderId` で選択します。音声パラメーター（声、音声フォーマット、速度など）は
それらのランタイムに組み込まれており、現時点ではユーザーが設定できません。音声対応の
プロバイダーは音声モデル id を宣言するだけでよく、アカウントを保存する、あるいはそれを
デフォルトプロバイダーに切り替えると、それらの種類が同じ OpenClaw 音声設定セクションへ
橋渡しされます。

音声プロバイダーを削除する、またはエージェントの**グローバル設定**で音声合成をオフにすると、
関連するエントリがそれらの音声設定セクションから再び削除され、設定済みのプロバイダーが
まだ残っていれば別のものがデフォルトに昇格します。

注意点：

- OpenAI TTS はベース URL を尊重しますが、カーネルのリアルタイム文字起こしエンドポイントは
  `api.openai.com` に固定されています（そこにはまだベース URL が適用されません）。
- リアルタイム音声には、音声プロバイダー id に一致するカーネル機能プラグインが必要です。
- Anthropic Claude には音声モデルがありません。Claude をチャットの頭脳として使い、
  別プロバイダーの TTS/ASR と組み合わせてください。
- 音声は設定によって厳密に制御されます。設定に `messages.tts` または文字起こし
  プロバイダーが指定されていない場合、対応する UI コントロール（🔊 再生ボタンと 🎙️ 録音
  ボタン）は無効化され、デスクトップは TTS／文字起こしの呼び出しを拒否します。
  内蔵の既定フォールバックはありません。

## マルチエージェント管理

複数のエージェントを作成・設定できます。それぞれが独自のモデル、有効スキル、チャネル
紐付けを持ちます。

- エージェント単位の**モデル上書き**（`provider/model`）。上書きのないエージェントは
  グローバルのデフォルトモデルを継承します。
- エージェント単位の**スキル許可リスト**（`agents.list[].skills`）。エージェントの作成・
  編集時に選択します。
- **チャネル紐付け** —— 各エージェントカードの**チャネルを紐付け**ボタンからモーダルを開き、
  複数のチャネルアカウントを一度にそのエージェントへ紐付けられます。各アカウントは同時に
  1 つのエージェントだけが扱います。
- **グローバル設定** —— デフォルトモデルの選択と、音声合成の有効化スイッチなどの
  グローバルな切り替え。

## マルチチャネル管理

複数の AI チャネルを同時に設定・監視できます。各チャネルは独立して動作するため、
異なるタスク向けに専用のエージェントを走らせられます。

各チャネルは複数アカウント、アカウント単位のエージェント紐付けに対応し、チャネルの
デフォルトアカウントを「チャネル」ページから直接切り替えられます。アカウントごとに
ライブの接続状態が表示されます。

カスタムのチャネルアカウント ID について、YYClaw は OpenClaw 互換の正規 ID を強制します。
`[a-z0-9_-]`、小文字、最大 64 文字、先頭は英数字です。これによりルーティングの不一致を
防ぎます。

YYClaw は Tencent 公式の個人向け WeChat チャネルプラグインを同梱しているため、「チャネル」
ページからアプリ内 QR フローで WeChat を直接連携できます。その他の同梱チャネルプラグインは
Feishu / Lark、WeCom、Discord、QQ、WhatsApp をカバーします。

Feishu アプリのワンクリック作成では、**クイックコマンド**のボットメニュー（`/new`、
`/stop`、`/reset`、`/status`、`/compact`）も自動設定されるため、ユーザーは入力する代わりに
ボットメニューをタップして OpenClaw のセッション制御を行えます。

## Cron ベースの自動化

AI タスクを自動実行するようスケジュールできます。トリガーと間隔を定義すれば、
エージェントは 24 時間体制で働けます。

「Cron」ページでは、外部配信をタスクフォーム内で直接設定でき、送信元アカウントと宛先
ターゲットを個別のセレクターで選べます。対応チャネルでは、宛先ターゲットがチャネルの
ディレクトリや既知のセッション履歴から自動的に検出されるため、`jobs.json` を手で編集する
必要はもうありません。タスクのメッセージ欄はメインのチャット入力欄と同じインラインの
`/skill` トークン記法（選択中のエージェントにスコープされる）でスキルを挿入できるため、
スケジュールされたプロンプトから直接スキルを起動できます。

スケジュールピッカーは**繰り返し**と**一度だけ**のタブに分かれています。繰り返しでは、
毎時、毎日、平日、毎週、そしてカスタムの生 cron 頻度を、インラインの時刻・曜日コントロール
とともに選べます。一度だけは、選んだ日付（曜日も表示）と時刻に一度だけタスクを実行します。
一度だけのタスクは未来の時点に設定する必要があり、完了するとランタイムが自動的に削除します。

SQLite ベースのランタイムへアップグレードすると、YYClaw は初回起動時に、従来の
`jobs.json` / `jobs.json.bak` から復元可能なユーザージョブを新しいストアへ黙って再作成し、
元のファイルを `~/.openclaw/cron/legacy-archive/` 配下にアーカイブします。
`[managed-by=...]` の内部ジョブはランタイムが再構築するよう残されます。

## 決定的ワークフローエンジン

手順が明確なタスク向けに、**ワークフロー**ページはメインプロセスで決定的オーケストレーション
エンジン（XState v5）を実行します。制御フロー —— どのノードが実行され、どの分岐が取られ、
どのループが繰り返されるか —— は 100% 固定です。非決定性を持つのは*モデル*（または
*エージェント*）ステップと明示的にマークされたノードのみで、それはスキーマ
（`temperature=0` に加えて zod 検証と上限付きリトライ）で制約され、決定的な経路へ
フォールバックできます。

各実行はノードごとのトレースを生成し、すべてのステップを**決定的**または**モデル**として
ラベル付けします。実行は `userData/workflows/` 配下にバージョン付き JSON スナップショットとして
永続化されるため、クラッシュしても完了済みのステップを再実行せずに再開でき、進捗は
`workflow:progress` イベントチャネル経由で UI にライブ配信されます。

エンジンは OpenClaw を駆動する側であり、その逆ではありません。決定的なステップは素の
メインプロセス関数として実行され、単一の制約付きモデルステップはエージェントループを
迂回して設定済みプロバイダーと直接やり取りします。

チャットタスクがワークフローへ自動振り分けされると、それはプロセスメッセージとして
**会話にインライン表示**されます。クエリの吹き出しはすぐに表示され、サーバーがタスクを
分解している間、入力欄は通常のターンと同じ*思考中*インジケーターを再利用します
（この間、ワークフローカードのコンパクトリンクは隠れたままです）。プランが確定すると
カードのリンクがその場に現れ、フローティングの進捗ポップオーバーが自動的に開きます。
カードをクリックすればポップオーバーを再度開け、外側をクリックすれば閉じられます。
各ノードは別個のトップレベルセッションではなく、メイン会話の子サブセッションとして実行され、
完了時には最終的にまとめられた応答が会話へ投稿されます。

## 拡張可能なスキルシステム

作り込まれたスキルで AI エージェントを拡張できます。統合された「スキル」ページはローカル
ファーストです。管理ディレクトリに加えて同梱・拡張・プラグインのスキルをスキャンし、
重複バージョンを防ぐためワークスペース、`.agents`、`skills.load.extraDirs` は除外します。
Gateway に依存せずスキルを有効／無効にでき、パッケージマネージャーは不要です。

「スキル」ページは各スキルの実際の場所を表示するので、本物のフォルダーを直接開けます。
同じメタデータ名またはスラッグを持つ管理スキルをインストールする際は確認を求められます。
確認された置き換えはトランザクショナルなので、インストールが失敗すると以前のコピーが
復元されます。

### 同梱スキル

YYClaw は [`anthropics/skills`](https://github.com/anthropics/skills) の完全な
ドキュメント処理スキル（`pdf`、`xlsx`、`docx`、`pptx`）と、厳選されたカタログ（GitHub、
tmux、Notion、Obsidian、Trello、天気など）をあらかじめ同梱しています。これらはビルド時に
スタンドアロンの `skills` CLI（`npx skills add …`、OpenClaw CLI とは独立）経由で取り込まれます。
すべて起動時に管理スキルディレクトリ（既定は `~/.openclaw/skills`）へ自動配置され、
初回インストール時に既定で有効化されます。プラットフォーム制限のあるスキル（Apple 関連など）
は macOS にのみ配置されます。

一部の同梱検索スキルは API キー（例：`TAVILY_API_KEY`、`BOCHA_API_KEY`）を必要とします。
キーがない場合は OpenClaw のランタイム設定エラーとして表面化します。

### サーバーマーケットプレイス

ルートの `package.json` にある単一の **`farmApiBaseUrl`**（スキーム、ホスト、ポートのみ。
例：`http://aiserver.example.com:9001`）がサーバー連携機能を駆動します。アプリはその
ベースの `GET /api/v1/provider-catalog` から AI プロバイダーカタログを読み込み、
**スキルをインストール**サイドパネル（サーバーソース）は同じベースの
`GET /api/v1/skill_list`（閲覧）、`GET /api/v1/skill_search?q=`（絞り込み）、
`GET /api/v1/skill_file/:name`（zip インストール）を使います。アプリ設定に Farm 認証
トークンが設定されている場合、任意の `Authorization: Bearer` ヘッダーが使われます。

サーバーマーケットプレイスのスキルをインストールする際は、同名の置き換え確認の前に、
まず ZIP の実際のスキル同一性を検証します。

## セキュアなプロバイダー統合

OpenAI、Anthropic、Z.AI / GLM を含む複数の AI プロバイダーに接続でき、資格情報は OS
ネイティブのキーチェーンに安全に保存されます。OpenAI は API キーと、Codex サブスクリプション
向けのブラウザ OAuth の両方に対応します。

OpenAI 互換ゲートウェイと組み合わせて使う**カスタム**プロバイダーでは、ヘッダーに敏感な
エンドポイント向けに **設定 → AI プロバイダー → プロバイダーを編集** でカスタム
`User-Agent` を設定できます。

プロバイダーを編集または切り替えるとき、YYClaw は `input: ["text", "image"]` のような
既存のモデル単位の機能メタデータを保持します。新しく選択したカスタムプロバイダーのモデルは
OpenClaw のオンボーディング互換な画像入力推論を使い、未知のモデルは既定でテキストのみに
なります。

カスタムプロバイダーのモデル行には、モデルファミリーから推論した明示的な `contextWindow`
も付与されます（例：`gpt-5.x` → 272k）。古いバージョンで保存された行は起動時に補完される
ため、OpenClaw は長いセッションが "Context overflow" で失敗する前に圧縮できます。圧縮設定が
存在しない場合、YYClaw は `agents.defaults.compaction.mode = "safeguard"` と
`reserveTokensFloor = 50000` を書き込みます。あなた自身が書いた行や設定は決して変更されません。
ただし欠落した `reserveTokensFloor` は補完されることがあります。

Z.AI（CN / Global）は OpenClaw 内蔵の `zai` プロバイダー（`ZAI_API_KEY`）にマッピングされます。
既定のモデルは `glm-5.2` です。Coding Plan のエンドポイント（`…/api/coding/paas/v4`）には
Code Plan プリセットを、通常の API エンドポイントには `…/api/paas/v4` を使います。CN と
Global は 1 つの OpenClaw ランタイムキーを共有するため、排他的です。

互換ゲートウェイが認証以外の理由で `/models` を拒否した場合、YYClaw は API キー検証中に、
設定済みモデルを使った軽量な `/chat/completions` または `/responses` プローブへ自動的に
フォールバックします。

> Moonshot（Kimi）に関する注記：YYClaw は Kimi のウェブ検索を既定で有効にしたままにします。
> Moonshot が設定されている場合、YYClaw は OpenClaw の設定で Kimi のウェブ検索を中国の
> エンドポイント（`https://api.moonshot.cn/v1`）にも同期します。

### トークン使用量の分析

「モデル」ページは、相対的なローリング 7 日間／30 日間ウィンドウ（暦月のバケットではありません）
でトークン使用量をグラフ化し、モデル別または時間別にグループ化し、キャッシュヒット率の計算と
エントリごとの詳細を提供します。時間別にグループ化した場合、グラフは選択したウィンドウ内の
すべての日バケットを保持します。上位エントリへの打ち切りが意図的に行われるのはモデル別の
グループ化のみです。

トークン使用量の履歴は、コンソールログの解析ではなく、ローカルの OpenClaw 設定ディレクトリ
配下のセッション記録 `.jsonl` ファイルから集計されます。設定済みのエージェントと、ディスク上で
見つかったランタイムのエージェントディレクトリの両方をスキャンし、通常の記録、
`.deleted.jsonl`、`.jsonl.reset.*` の記録をいずれも有効な履歴ソースとして扱い、
`message.usage` を持つアシスタント／ツールの使用量レコードを抽出します。読み取りは
mtime／サイズをキーにした差分キャッシュを使うため、大きなセッションディレクトリでも
メインプロセスでファイル全体の再スキャンが繰り返されることはありません。

## 画像生成

開発者モードでは、専用の**画像生成**ページが独立した OpenAI 互換の画像生成エンドポイント
（ベース URL、API キー、`gpt-image-2` などのモデル名）に対応するため、チャットは通常の
OpenAI プロバイダーを使い続けたまま、画像生成は専用の `/v1/images/generations` サービスを
利用できます。

チャットでの自然言語による画像生成には、その開発者向けページは不要です。**設定 → AI
プロバイダー** でいずれかのプロバイダーアカウントに `image_generate` のモデル種別を与えれば、
そのプロバイダーキー（例：`gptimage2-gptimage/gpt-image-2`）がそのまま機能します。
YYClaw の 2 つの同梱画像プラグインは、どのプロバイダーキーが自分のモデルファミリーを
ホストしているかを `openclaw.json` から自己検出し（`clawx-openai-image` は
`gpt-image-*` / `dall-e-*`、`clawx-gemini-image` は `gemini-*-image`）、それらのキーを
エイリアスとして登録します。したがって新しい `models.providers` エントリは作られず、
API キーもコピーされません。

これは、OpenClaw が画像生成レジストリに登録されたプロバイダーに対してのみ画像生成を
解決するためです。素の `models.providers` エントリだけでは決して条件を満たしません。
`imageGenerationModel.primary` に既に固定されているモデル id がワイヤープロトコルを決めるので、
リクエスト時に何も探索されません。どちらのファミリーにも属さないモデル（例：minimax の
`image-01`、Google の `imagen-*`）は OpenClaw 自身の内蔵プロバイダーに委ねられます。

2 つのプラグインの分割は装飾ではなく必然です。OpenAI 互換のリレーは
`/v1/images/generations` で imagen 以外の Gemini モデルを拒否し、OpenClaw 内蔵の `google`
画像プロバイダーはベース URL を `generativelanguage.googleapis.com` に固定するため、
リレーとして機能できません。YYClaw の起動前ステップは、どちらかのプラグインが必要になった
時点で `agents.defaults.mediaGenerationAutoProviderFallback = false` も設定します。
これにより、リレーが生成できないモデルは、別の認証済みプロバイダー経由で黙って描画される
のではなく、リレー自身のエラーで失敗します。

## OpenClaw Dreams

システム設定の**メモリ**タブは、OpenClaw `memory-core` の dreaming —— バックグラウンドの
メモリ統合 —— を管理し、状態、日記、メンテナンス、有効／無効をカバーします。動作中の
Gateway と、OpenClaw 側で設定された dreaming プラグインが必要です。

## アダプティブテーマ

ライトモード、ダークモード、またはシステム同期のテーマを選べます。YYClaw は温かみのある
パレットで自動的に好みに合わせ、ユーザーに見えるすべての文字列は `react-i18next` 経由で
`en`、`zh`、`ja`、`ru` にわたって提供されます。

## 自動起動設定

**設定 → 一般** で**システム起動時に起動**を有効にすると、ログイン後に YYClaw が自動的に
起動します。

## 更新通知

YYClaw は起動時に新しいバージョンを確認します。更新が利用可能な場合はアプリ内で通知を
表示し、ダウンロードとインストールはあなたが操作を選んだ後にのみ行われます。

**macOS：** アプリ内更新（自動、または**インストールして再起動**を選んだ場合）のためには、
DMG から YYClaw を **/Applications** にコピーし、そこから実行してください。マウントされた
DMG やその他の読み取り専用ボリュームから直接起動すると、アップデーターがアプリバンドルを
置き換えられず、インストール手順が何もしていないように見えることがあります。

### メンテナー向け

メインプロセスは `{CDN}/{channel}/` 配下の generic-provider フィードを確認します。channel は
アプリの semver に従います（stable → `latest`）。ユーザーにアップグレードを**強制**するには、
その channel の `*-mac.yml` / `*.yml` の**ルート**に `forceUpdate: true` を公開すると、
`electron-updater` がそれを UI へ渡します。channel ディレクトリはアプリのプレリリースタグと
一致していなければならず、そうでないと安定版ビルドが誤ったマニフェストを読みます。

## セッションメンテナンス

開発者モードを有効にした **設定 → 詳細** では、**セッション自動クリーンアップポリシー**
フォームが `session.maintenance`（mode / pruneAfter / maxEntries / maxDiskBytes）を
`openclaw.json` に書き込むため、Gateway は自身のスケジュールで古いセッションや予算超過の
セッションを削除します。`mode` の既定値は `enforce` で、未設定の場合は起動時に自動的に
書き込まれます。`~/.openclaw/agents/*/sessions/` 配下のセッション記録は追記専用で、
数 GB に達することがあります。

## 設定の保存

すべての設定ファイル（`openclaw.json` と `auth-profiles.json` を含む）は、開発ビルドでも
本番ビルドでもディスク上に**プレーンテキスト**として書き込まれます。これは OpenClaw 上流の
設定ヘルス監視機構との衝突を緩和するためです。この機構は、パースやサイズが予期せず変化すると
`.clobbered` バックアップファイルを生成することがあります。過去の暗号化された設定
（`CLAWX_ENCRYPTED_v1:`）の読み取りは引き続きサポートされます。
