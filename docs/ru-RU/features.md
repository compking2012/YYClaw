# Возможности YYClaw

## Видение продукта и целевой охват

YYClaw стремится стать **открытой, независимой от поставщиков кроссплатформенной AI-средой** с контролем приватности и стоимости, надёжностью, расширяемостью и аудитом. Общая среда Agent объединяет десктоп, мобильную/планшетную консоль и постоянный Linux-сервер пользователя. Шесть принципов: MIT и свобода моделей, единый опыт с ограничениями ОС, локально-облачная работа, мультимодальность, детерминированная автоматизация с аудитом, глобальная и китайская экосистемы.

Сценарии включают код и эксплуатацию для разработчиков, приватные материалы и публикации для авторов, IM и клиентов для малых команд, закрытые данные и литературу для исследователей/преподавателей. Цель охватывает экран, голос, документы, видео; текст, графики, изображения, речь, видеосценарии; XState с явными узлами рассуждения, повторами, согласованием и восстановлением; изоляцию Agent; прослеживаемый Cron; облачные/локальные модели, MCP, международные инструменты, Feishu/Lark, DingTalk, WeCom.

**Это цели, а не гарантия уже поставленных функций.** Мобильные клиенты, удалённое управление, синхронизация, размещение и миграция остаются требованиями. Чувствительные задачи и локальные операции остаются на устройстве; разрешённые длительные задачи могут работать в облаке. Локальный Agent с облачной моделью не означает отсутствие передачи данных. См. [полный PRD](../PRODUCT.md) и [статус поставки](../FEATURELIST.md); далее описаны текущие десктопные функции.

Вариант слогана: *One Workbench, All Devices, Any Model.* — Одна рабочая среда, все устройства, любые модели.

Отдельная страница генерации изображений в боковой панели сохраняется и доступна в режиме разработчика. Она использует общие интегрированные настройки эндпоинта вместе с локальными настройками разработчика; управление моделями остаётся в локальном диалоге настроек.

В локальный каталог добавлены браузерная авторизация и настройка API-ключа TokenDance с правилами отображения для китайского интерфейса и идентификацией запросов из upstream. Для Anthropic и Google добавлены параметры подключения upstream. Существующие идентификаторы моделей, значения по умолчанию, слоты возможностей, выбор удалённого или локального каталога и резервный режим разработчика сохранены.

Этот документ — подробное дополнение к разделу «Возможности» в
[README](../../README.ru-RU.md). Здесь собраны нюансы реализации, ограничения и
механика конфигурации, слишком детальные для самого README.


### Интеграция возможностей upstream

Поле ввода сохраняет локальные имена аккаунтов и выбор модели только для текущего диалога. Использование контекста ACP отображается перед статусом Gateway; новые данные среды выполнения приоритетны. Сжатие и просмотр дочерних агентов только для чтения сосуществуют с независимой лентой рабочих процессов. `@agent` начинает новый диалог целевого агента.

Резерв сжатия пересчитывается только при смене глобальной модели диалога: 25% явно заданного контекста или 50 000 токенов без метаданных. Переопределения агентов, медиаслоты и синхронизация при запуске не меняют резерв; явные настройки сохраняются.

DingTalk использует официальный upstream-коннектор с локальными несколькими аккаунтами и необязательной авторизацией рабочего пространства. Computer Use сохраняет upstream-жизненный цикл локального драйвера и разрешения. Настройки → О программе экспортируют обезличенную диагностику и явно выбранные исходные диалоги в локальный ZIP без автоматической отправки.

## Нулевой порог настройки

Пройдите весь путь от установки до первого разговора с AI через понятный
графический интерфейс. Команды в терминале, YAML-файлы и поиск переменных
окружения не нужны.

Мастер первого запуска охватывает **язык и регион** (системный язык выбирается
заранее, если поддерживается, иначе английский), **AI-провайдера** (API-ключ или
OAuth через браузер/устройство, где провайдер это поддерживает), **наборы
навыков** и шаг **проверки**. По завершении сохраняется признак «настройка
завершена» и происходит переход в чат. Мастер можно пропустить, интерфейс
полностью доступен без ключей провайдеров, и готовность Gateway для завершения
настройки не требуется.

## Интеллектуальный интерфейс чата

Общайтесь с AI-агентами в современном интерфейсе чата. YYClaw поддерживает
несколько контекстов разговора и историю сообщений, а ответы ассистента
отображаются как потоковый Markdown с подсветкой синтаксиса в блоках кода,
корректным разбором CJK, таблицами в стиле GitHub и математикой LaTeX на движке
KaTeX (`$inline$`, `$$block$$`, `\(inline\)`, `\[block\]`). Ввод пользователя
остаётся обычным текстом. Основное поле ввода также поддерживает прямую
маршрутизацию `@agent` для конфигураций с несколькими агентами. Блоки кода
сохраняют исходные переводы строк, мягко переносят длинные строки и предлагают
локализованное действие копирования после завершения потоковой передачи.

Навыки, вставленные из поля ввода, отображаются как карточки `/skill-name`.
Щёлкните карточку, чтобы открыть боковую панель предпросмотра и прочитать
`SKILL.md` этого навыка.

Когда вы обращаетесь к другому агенту через `@agent`, YYClaw переключается прямо
в его собственный контекст разговора, а не передаёт запрос через агента по
умолчанию. Рабочие области агентов по умолчанию раздельны, а более строгая
изоляция во время выполнения зависит от настроек песочницы OpenClaw.

Когда настроено несколько моделей, в поле ввода появляется переключатель
**модели**. Изменения модели применяет штатный наблюдатель конфигурации OpenClaw
без перезапуска Gateway; YYClaw ждёт, пока живой снимок `agents.list` не отразит
выбранную модель, и только затем разрешает следующую отправку. Навыки действуют на
уровне агента (`agents.list[].skills`): при создании или изменении агента можно
выбрать его включённые навыки, а прежние глобальные переключатели навыков
однократно переносятся в каждого существующего агента для обратной совместимости.

### Боковая панель сессий

Боковая панель сессий ориентирована на рабочие области: рабочая область по
умолчанию закреплена сверху, остальные сортируются естественным образом, и каждую
можно свернуть или подгрузить больше сессий. Строка сессии показывает индикатор,
пока AI отвечает, синюю точку, когда завершился непрочитанный ответ, и
относительное время активности после открытия разговора; при наведении по-прежнему
появляются действия строки. Импортированные рабочие области можно переименовать в
заголовке боковой панели. Своё название отражается в поле ввода чата, а при
наведении на заголовок по-прежнему виден путь в файловой системе.

Когда выбрана корректная рабочая область, новый чат наследует её и остаётся
изменяемым до первой отправки. Изменяемые новые или несвязанные чаты показывают в
поле ввода чип рабочей области. Его меню перечисляет недавние и известные по
сессиям рабочие области, позволяет вернуться к области по умолчанию или выбрать
другую папку. Если сохранённая папка рабочей области была перемещена или удалена,
чат приостанавливает создание сессии и просит выбрать существующую папку вместо
повторных попыток обратиться к отсутствующему пути. Недоступные группы, отличные
от группы по умолчанию, помечаются в боковой панели и могут быть удалены после
подтверждения; это безвозвратно удаляет все сессии этой группы. Строка сессии
исчезает и навигация меняется только после успешного безвозвратного удаления.
Неудачные удаления оставляют разговор и подтверждение открытыми для повтора.

Синтетические резервные заголовки OpenClaw из UUID и даты считаются отсутствующими
только тогда, когда совпадают с идентификатором сессии, и затем заменяются первым
запросом пользователя из разговора вместо сохранения в качестве имени сессии.

При холодном старте или после перезапуска Gateway — если вы ещё не открыли
конкретный разговор — чат оказывается в совершенно новом пустом разговоре, а не
восстанавливает последнюю обновлённую сессию; существующие сессии остаются в
списке боковой панели.

### Предпросмотр документов

Вкладки «Рабочая область» и «Предпросмотр» в правой панели чата дают предпросмотр
только для чтения файлов Markdown, `.docx` и `.pptx`. Предпросмотр Markdown в
режиме статического рендеринга использует ту же подсветку синтаксиса, мягкий
перенос, копируемые блоки кода, корректный разбор CJK и поддержку математики
KaTeX. Заголовок предпросмотра может развернуть выбранный файл на весь экран
YYClaw; тем же элементом управления или клавишей Escape можно вернуться к панели.

Ограничения: устаревшие `.doc` и `.ppt` открываются через операционную систему, а
не внутри приложения; разбиение DOCX на страницы может отличаться от Microsoft
Word; предпросмотр PPTX не поддерживает анимацию, переходы и воспроизведение
мультимедиа; файлы Office больше 20 МБ не отображаются внутри приложения.

## Предпросмотр локального HTML

Правая панель чата содержит вкладки «Рабочая область», «Предпросмотр» и
«Изменения». Она не предоставляет универсальный веб-браузер, домашнюю страницу или
адресную строку. Разрешённые локальные вложения `.html` и `.htm`, файловая
активность и файлы рабочей области по умолчанию открываются в «Предпросмотре».
Действия с файлом позволяют выбрать встроенный предпросмотр или системное
приложение, а из заголовка предпросмотра можно открыть текущий HTML-файл в
системном браузере.

Все ссылки некликабельны. Ссылки, отрисованные YYClaw, выглядят как обычный текст,
а у ссылок внутри предпросмотра HTML убраны стили и обработка указателя.
Предпросмотр HTML также блокирует формы, навигацию скриптами, перенаправления,
навигацию по хэшу, всплывающие окна, загрузки, сетевые запросы и разрешения
устройств. Он может отрисовать самодостаточный локальный HTML, но не может
выйти за пределы выбранного документа.

## Голосовое взаимодействие

Говорите с агентами и слушайте их ответы. Голос работает полностью через штатные
Talk/TTS Gateway RPC ядра OpenClaw — без дополнительных сервисов.

- **Голосовой ввод** использует **режим Talk** в OpenClaw. *Диктовка* (нажми и
  говори) переводит речь в поле ввода для проверки перед отправкой; режим
  *разговора* открывает непрерывный диалог без рук (слушать → думать → говорить) с
  серверным определением речевой активности и возможностью перебить. Режим
  выбирается в **Настройки → Голос**.
- **Голосовой вывод (TTS)**: у каждого ответа ассистента есть кнопка 🔊, а
  **Настройки → Голос → Автоозвучивание** может читать итоговые ответы
  автоматически.
- Доступ к микрофону запрашивается при первом использовании; на macOS приложение
  запрашивает системное разрешение на микрофон.

### Настройка голосовых моделей

Голосовые модели перечислены на странице **Модели** рядом с провайдерами чата.
Определения провайдеров берутся из удалённого каталога провайдеров, когда он
доступен, иначе — из встроенного `resources/config/providers.json` (это
взаимоисключающие источники, они не объединяются). Поэтому набор предлагаемых типов
возможностей, включая `tts` / `transcription` / `realtime`, зависит от источника.

Настройте API-ключ, модель и базовый URL провайдера; выбранное записывается в
конфигурацию OpenClaw (`messages.tts` и плагин `voice-call`). В этом выпуске
поддерживаются две встроенные голосовые среды — **OpenAI** и **MiniMax**,
выбираемые через `voiceRuntimeProviderId` провайдера. Параметры голоса (голос,
формат аудио, скорость и так далее) встроены в эти среды и пока не настраиваются
пользователем: провайдеру с поддержкой голоса достаточно объявить идентификатор
голосовой модели, а сохранение аккаунта — или переключение его в провайдера по
умолчанию — переносит эти типы в те же секции голосовой конфигурации OpenClaw.

Удаление голосового провайдера или отключение синтеза речи в **Общей конфигурации**
агентов снова убирает связанные записи из этих секций, повышая другого настроенного
провайдера до значения по умолчанию, если он ещё есть.

Нюансы:

- OpenAI TTS учитывает базовый URL, но эндпоинт распознавания в реальном времени в
  ядре зафиксирован на `api.openai.com` (базовый URL там пока не применяется).
- Голос в реальном времени требует плагина возможностей ядра, соответствующего
  идентификатору голосового провайдера.
- У Anthropic Claude нет речевых моделей — используйте Claude как «мозг» чата в
  паре с TTS/ASR другого провайдера.
- Голос строго зависит от конфигурации: если `messages.tts` или провайдер
  распознавания не заданы, соответствующие элементы интерфейса (кнопка 🔊 и кнопка
  записи 🎙️) отключаются, и приложение отклоняет вызовы TTS/распознавания.
  Встроенного резервного варианта по умолчанию нет.

## Управление несколькими агентами

Создавайте и настраивайте несколько агентов, у каждого своя модель, включённые
навыки и привязка к каналам:

- **Переопределение модели** на уровне агента (`provider/model`); агенты без
  переопределения наследуют глобальную модель по умолчанию.
- **Список разрешённых навыков** на уровне агента (`agents.list[].skills`),
  выбираемый при создании или изменении агента.
- **Привязка каналов** — у каждой карточки агента есть кнопка **Привязать каналы**,
  открывающая модальное окно для привязки сразу нескольких аккаунтов каналов к
  этому агенту. Каждый аккаунт в один момент обслуживает один агент.
- **Общая конфигурация** — выбор модели по умолчанию и глобальные переключатели,
  например включение синтеза речи.

## Управление несколькими каналами

Настраивайте и наблюдайте за несколькими AI-каналами одновременно. Каждый канал
работает независимо, что позволяет запускать специализированных агентов под разные
задачи.

Каждый канал поддерживает несколько аккаунтов, привязку агента к аккаунту и
переключение аккаунта канала по умолчанию прямо со страницы «Каналы». Для каждого
аккаунта отображается актуальный статус подключения.

Для собственных идентификаторов аккаунтов каналов YYClaw требует канонические
идентификаторы, совместимые с OpenClaw: `[a-z0-9_-]`, нижний регистр, максимум 64
символа, первый символ — буква или цифра. Это предотвращает несовпадения
маршрутизации.

YYClaw включает официальный плагин персонального канала WeChat от Tencent, поэтому
подключить WeChat можно прямо со страницы «Каналы» через QR-процесс в приложении.
Остальные встроенные плагины каналов охватывают Feishu / Lark, WeCom, Discord, QQ
и WhatsApp.

Создание приложения Feishu в один клик также автоматически настраивает меню бота
**Быстрые команды** (`/new`, `/stop`, `/reset`, `/status`, `/compact`), чтобы
пользователи управляли сессией OpenClaw нажатием в меню бота, а не набором текста.

## Автоматизация по расписанию

Планируйте автоматический запуск AI-задач. Задайте триггеры и интервалы, и агенты
смогут работать круглосуточно.

Страница «Расписание» позволяет настроить внешнюю доставку прямо в форме задачи, с
отдельными селекторами аккаунта-отправителя и получателя. Для поддерживаемых
каналов получатели определяются автоматически из справочников каналов или известной
истории сессий, поэтому править `jobs.json` вручную больше не нужно. Поле сообщения
задачи поддерживает вставку навыков тем же встроенным синтаксисом токенов
`/skill`, что и основное поле чата, в пределах выбранного агента, поэтому
запланированные промпты могут запускать навыки напрямую.

Выбор расписания разделён на вкладки **Повторяющееся** и **Однократно**.
Повторяющееся предлагает частоты «каждый час», «ежедневно», «по рабочим дням»,
«еженедельно» и произвольное cron-выражение с встроенными элементами выбора времени
и дней недели. Однократно выполняет задачу один раз в выбранную дату (с указанием
дня недели) и время. Однократные задачи должны быть назначены на будущий момент и
автоматически удаляются средой выполнения после завершения.

При переходе на среду выполнения на базе SQLite YYClaw при первом запуске молча
пересоздаёт в новом хранилище все восстановимые пользовательские задачи из прежних
`jobs.json` / `jobs.json.bak` и архивирует оригиналы в
`~/.openclaw/cron/legacy-archive/`. Внутренние задачи `[managed-by=...]`
оставляются среде выполнения для пересборки.

## Детерминированный движок процессов

Для задач с ясно определёнными шагами страница **Процессы** запускает
детерминированный движок оркестрации (XState v5) в главном процессе. Поток
управления — какой узел выполняется, какая ветка выбирается, какой цикл
повторяется — зафиксирован на 100%; недетерминизм несут только узлы, явно
помеченные как шаги *модели* (или *агента*), и он ограничен схемой
(`temperature=0` плюс валидация zod и ограниченное число повторов) и может
переключиться на детерминированный путь.

Каждый запуск даёт трассировку по узлам, помечая каждый шаг как
**детерминированный** или **модельный**. Запуски сохраняются как версионированные
JSON-снимки в `userData/workflows/`, поэтому после сбоя возобновляются без
повторного выполнения завершённых шагов, а прогресс транслируется в интерфейс через
канал событий `workflow:progress`.

Движок управляет OpenClaw, а не наоборот: детерминированные шаги выполняются как
обычные функции главного процесса, а единственный ограниченный модельный шаг
обращается к настроенному провайдеру напрямую, минуя цикл агента.

Когда задача чата автоматически направляется в процесс, она появляется **внутри
переписки** как служебное сообщение. Пузырь запроса показывается сразу, и пока
сервер декомпозирует задачу, поле ввода использует тот же индикатор *размышления*,
что и обычный ход (компактная ссылка карточки процесса в это время скрыта). Как
только план готов, ссылка карточки появляется на своём месте, и её всплывающий
индикатор прогресса открывается автоматически; карточку можно щёлкнуть, чтобы снова
открыть всплывающее окно, или щёлкнуть в стороне, чтобы закрыть. Каждый узел
выполняется как дочерняя подсессия основной переписки, а не как отдельная сессия
верхнего уровня, и по завершении в переписку публикуется итоговый сводный ответ.

## Расширяемая система навыков

Расширяйте AI-агентов готовыми навыками. Встроенная страница «Навыки» работает
локально: она сканирует управляемый каталог, а также встроенные, расширенные и
плагинные навыки, исключая рабочую область, `.agents` и
`skills.load.extraDirs`, чтобы избежать дублирующихся версий. Включать и отключать
навыки можно без Gateway — менеджеры пакетов не нужны.

Страница «Навыки» показывает фактическое расположение каждого навыка, так что можно
открыть настоящую папку. Установка управляемого навыка с тем же именем в метаданных
или тем же slug запрашивает подтверждение; подтверждённая замена транзакционна,
поэтому неудачная установка восстанавливает предыдущую копию.

### Встроенные навыки

YYClaw заранее включает полные навыки обработки документов (`pdf`, `xlsx`, `docx`,
`pptx`) из [`anthropics/skills`](https://github.com/anthropics/skills), а также
отобранный каталог (GitHub, tmux, Notion, Obsidian, Trello, погода и другое),
собираемый на этапе сборки через отдельный CLI `skills` (`npx skills add …`,
независимый от CLI OpenClaw). Всё это автоматически разворачивается в управляемый
каталог навыков (по умолчанию `~/.openclaw/skills`) при запуске и включается по
умолчанию при первой установке. Навыки с платформенными ограничениями, например
для Apple, разворачиваются только на macOS.

Некоторым встроенным навыкам поиска нужны API-ключи (например `TAVILY_API_KEY`,
`BOCHA_API_KEY`); отсутствие ключей проявляется как ошибки конфигурации среды
выполнения OpenClaw.

### Серверный маркетплейс

Единственный параметр **`farmApiBaseUrl`** в корневом `package.json` (только схема,
хост и порт, например `http://aiserver.example.com:9001`) управляет серверными
возможностями. Приложение загружает каталог AI-провайдеров из
`GET /api/v1/provider-catalog` по этому адресу, а боковая панель **Установить
навыки** (серверный источник) использует тот же адрес для
`GET /api/v1/skill_list` (просмотр), `GET /api/v1/skill_search?q=` (фильтр) и
`GET /api/v1/skill_file/:name` (установка zip). Необязательный заголовок
`Authorization: Bearer` использует токен Farm из настроек приложения, если он задан.

При установке навыка из серверного маркетплейса сначала проверяется фактическая
идентичность навыка в ZIP, и только затем запрашивается подтверждение замены
одноимённого.

## Безопасная интеграция провайдеров

Подключайтесь к нескольким AI-провайдерам, включая OpenAI, Anthropic и Z.AI / GLM,
с надёжным хранением учётных данных в системном хранилище ключей. OpenAI
поддерживает и API-ключи, и OAuth в браузере для подписок Codex.

Для **собственных** провайдеров, используемых с OpenAI-совместимыми шлюзами, можно
задать свой `User-Agent` в **Настройки → AI-провайдеры → Изменить провайдера** для
чувствительных к заголовкам эндпоинтов.

При изменении или переключении провайдеров YYClaw сохраняет существующие метаданные
возможностей по моделям, например `input: ["text", "image"]`. Вновь выбранные
модели собственных провайдеров используют совместимый с онбордингом OpenClaw вывод
о поддержке изображений на входе, а неизвестные модели по умолчанию считаются
только текстовыми.

Строки моделей собственных провайдеров также получают явный `contextWindow`,
выведенный из семейства модели (например `gpt-5.x` → 272k). Строки, сохранённые
более старыми версиями, дозаполняются при запуске, чтобы OpenClaw мог сжимать
длинные сессии до того, как они завершатся ошибкой «Context overflow». Если
конфигурации сжатия нет, YYClaw задаёт
`agents.defaults.compaction.mode = "safeguard"` и `reserveTokensFloor = 50000`;
строки и конфигурации, написанные вами, никогда не изменяются, за исключением того,
что отсутствующий `reserveTokensFloor` может быть дозаполнен.

Z.AI (CN / Global) сопоставляется со встроенным провайдером `zai` в OpenClaw
(`ZAI_API_KEY`). Модель по умолчанию — `glm-5.2`. Для эндпоинтов Coding Plan
(`…/api/coding/paas/v4`) используйте предустановку Code Plan, для обычных
эндпоинтов API — `…/api/paas/v4`. CN и Global взаимоисключающие, поскольку
используют один ключ среды выполнения OpenClaw.

Когда совместимый шлюз отклоняет `/models` по причинам, не связанным с
аутентификацией, YYClaw при проверке API-ключа автоматически переходит к
облегчённому запросу `/chat/completions` или `/responses` с настроенной моделью.

> Примечание про Moonshot (Kimi): YYClaw по умолчанию оставляет веб-поиск Kimi
> включённым. Когда Moonshot настроен, YYClaw также синхронизирует веб-поиск Kimi с
> китайским эндпоинтом (`https://api.moonshot.cn/v1`) в конфигурации OpenClaw.

### Аналитика расхода токенов

Страница «Модели» строит графики расхода токенов по относительным скользящим окнам
7 и 30 дней (а не по календарным месяцам), с группировкой по модели или по времени,
расчётом доли попаданий в кэш и детализацией по записям. При группировке по времени
график сохраняет все дневные интервалы выбранного окна; намеренное ограничение
верхними позициями применяется только к группировке по модели.

История расхода токенов агрегируется из файлов журналов сессий `.jsonl` в локальном
каталоге конфигурации OpenClaw, а не разбирается из логов консоли. Сканируются как
настроенные агенты, так и любые найденные на диске каталоги агентов среды
выполнения, при этом обычные журналы, `.deleted.jsonl` и `.jsonl.reset.*`
считаются допустимыми источниками истории, из которых извлекаются записи расхода
ассистента и инструментов, содержащие `message.usage`. Чтение использует
инкрементальный кэш по mtime и размеру, поэтому большой каталог сессий не приводит
к повторному полному пересканированию файлов в главном процессе.

## Генерация изображений

В режиме разработчика отдельная страница **Генерация изображений** поддерживает
независимый OpenAI-совместимый эндпоинт генерации изображений (базовый URL,
API-ключ и имя модели, например `gpt-image-2`), поэтому генерация изображений может
использовать выделенный сервис `/v1/images/generations`, пока чат продолжает
работать с обычным провайдером OpenAI.

Генерация изображений на естественном языке в чате не требует этой страницы для
разработчиков. Присвойте любому аккаунту провайдера вид модели `image_generate` в
**Настройки → AI-провайдеры**, и его собственный ключ провайдера (например
`gptimage2-gptimage/gpt-image-2`) сработает напрямую: два встроенных плагина
изображений YYClaw сами определяют по `openclaw.json`, какие ключи провайдеров
обслуживают их семейство моделей (`gpt-image-*` / `dall-e-*` для
`clawx-openai-image`, `gemini-*-image` для `clawx-gemini-image`), и регистрируют эти
ключи как псевдонимы, поэтому новая запись `models.providers` не создаётся и
API-ключ не копируется.

Это нужно потому, что OpenClaw разрешает генерацию изображений только для
провайдеров, зарегистрированных в его реестре генерации изображений — обычная
запись `models.providers` сама по себе никогда не подходит. Идентификатор модели,
уже зафиксированный в `imageGenerationModel.primary`, определяет протокол передачи,
поэтому во время запроса ничего не зондируется; модель, не входящая ни в одно
семейство (например `image-01` от minimax или `imagen-*` от Google), остаётся на
встроенных провайдерах самого OpenClaw.

Разделение на два плагина необходимо, а не косметично: OpenAI-совместимые ретрансляторы
отклоняют не-imagen модели Gemini на `/v1/images/generations`, а встроенный провайдер
изображений `google` в OpenClaw фиксирует базовый URL на
`generativelanguage.googleapis.com`, поэтому не может обслуживать ретранслятор. Шаг
предзапуска YYClaw также выставляет
`agents.defaults.mediaGenerationAutoProviderFallback = false`, когда нужен любой из
плагинов, чтобы модель, которую ретранслятор не может сгенерировать, завершалась с
собственной ошибкой ретранслятора, а не отрисовывалась молча через другого
аутентифицированного провайдера.

## OpenClaw Dreams

Вкладка **Память** в системных настройках управляет «сновидениями» `memory-core` в
OpenClaw — фоновой консолидацией памяти — включая состояние, дневник, обслуживание
и включение/отключение. Требуется работающий Gateway и настроенный на стороне
OpenClaw плагин сновидений.

## Адаптивные темы

Выберите светлую тему, тёмную или синхронизированную с системой. YYClaw
автоматически подстраивается под ваши предпочтения, используя тёплую палитру, а все
пользовательские строки проходят через `react-i18next` для `en`, `zh`, `ja` и `ru`.

## Управление автозапуском

В **Настройки → Общие** включите **автозапуск при входе в систему**, чтобы YYClaw
запускался автоматически после входа.

## Запросы на обновление

YYClaw проверяет новые версии при запуске. Когда обновление доступно, показывается
запрос внутри приложения; загрузка и установка происходят только после того, как вы
выберете действие.

**macOS:** для обновлений внутри приложения (автоматических или когда вы выбираете
**Установить и перезапустить**) скопируйте YYClaw из DMG в **/Applications** и
запускайте оттуда. Если запустить приложение прямо из смонтированного DMG или
другого тома только для чтения, механизм обновления может не суметь заменить бандл
приложения, и шаг установки будет выглядеть так, будто ничего не произошло.

### Для сопровождающих

Главный процесс проверяет фид generic-provider по адресу `{CDN}/{channel}/`, где
канал соответствует semver приложения (stable → `latest`). Чтобы **заставить**
пользователей обновиться, опубликуйте `forceUpdate: true` в **корне** файлов
`*-mac.yml` / `*.yml` этого канала, и `electron-updater` передаст это в интерфейс.
Каталог канала должен соответствовать prerelease-тегу приложения, иначе стабильные
сборки прочитают не тот манифест.

## Обслуживание сессий

В **Настройки → Расширенные** при включённом режиме разработчика форма **Политика
автоочистки сессий** записывает `session.maintenance` (mode / pruneAfter /
maxEntries / maxDiskBytes) в `openclaw.json`, чтобы Gateway сам по своему расписанию
удалял старые или превышающие бюджет сессии. `mode` по умолчанию равен `enforce` и
задаётся автоматически при запуске, если не установлен. Журналы сессий в
`~/.openclaw/agents/*/sessions/` пишутся только добавлением и могут достигать
нескольких гигабайт.

## Хранение конфигурации

Все файлы конфигурации (включая `openclaw.json` и `auth-profiles.json`) пишутся на
диск **в виде обычного текста** и в отладочных, и в production-сборках. Это
снижает конфликты с механизмом наблюдения за состоянием конфигурации в upstream
OpenClaw, который может создавать резервные файлы `.clobbered`, если разбор или
размер неожиданно меняются. Чтение исторических зашифрованных конфигураций
(`CLAWX_ENCRYPTED_v1:`) по-прежнему поддерживается.
