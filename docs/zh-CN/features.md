# YYClaw 功能特性

本文仅介绍已经实现的桌面功能，明确说明配置前提、开发者模式开关与使用限制，不包含产品路线图。

## 零配置门槛

从安装到第一次 AI 对话，全流程都可以在直观的图形界面中完成，无需终端命令、YAML 文件，
也不必四处翻找环境变量。

首次启动的向导覆盖**语言与地区**（系统语言受支持时预选，否则回退英文）、
**AI 供应商**（API Key，或在供应商支持时使用浏览器 / 设备 OAuth）、**技能包**，
以及**验证**步骤。完成后会写入持久化的「配置完成」标记并跳转到聊天页。向导可以跳过，
没有供应商密钥时界面依然可以完整浏览，且完成配置并不要求 Gateway 已就绪。

## 智能聊天界面

通过现代化的聊天体验与 AI 智能体交流。YYClaw 支持多个会话上下文与消息历史；助手回复以
流式 Markdown 渲染，包含语法高亮的围栏代码块、面向中日韩文本的解析、GitHub 风格表格，
以及由 KaTeX 渲染的 LaTeX 数学公式（`$行内$`、`$$块级$$`、`\(行内\)`、`\[块级\]`）。
用户输入始终按原始文本显示。主输入框还支持面向多智能体场景的 `@agent` 直接路由。
围栏代码会保留源码换行、对长行自动软换行，并在流式输出结束后提供本地化的复制操作。

从输入框插入的技能会以 `/技能名` 卡片形式显示。点击卡片可在右侧预览栏打开并阅读该技能的
`SKILL.md`。

当你用 `@agent` 指向另一个智能体时，YYClaw 会直接切换到该智能体自己的会话上下文，
而不是经由默认智能体转发。智能体工作区默认相互独立，更强的运行时隔离取决于 OpenClaw
的沙箱设置。

配置多个模型后，输入框的模型选择器显示账号名称。选择模型只影响当前会话，不改变智能体默认模型，也不重启 Gateway。

聊天界面显示上下文用量和压缩状态，帮助你了解当前会话的容量。子智能体任务支持查看实时状态、打开只读子会话，以及返回父会话；工作流任务提供独立的进度时间线。

修改全局默认对话模型时，压缩预留按显式上下文窗口的 25% 计算；缺少该元数据时使用 50,000 token。智能体模型覆盖、媒体能力槽位和启动同步不重新计算，用户显式压缩设置优先。

### 会话侧边栏

会话侧边栏以工作区为先：默认工作区固定在最上方，其他工作区自然排序，每个工作区都可以
折叠或加载更多会话。会话行在 AI 回复期间显示加载指示，出现未读回复时显示蓝点，
打开会话后显示相对活动时间；悬停仍会露出行内操作。导入的工作区可以在其侧栏标题处重命名，
自定义名称会反映到聊天输入框，而悬停标题仍可看到文件系统路径。

选中了有效工作区时，新会话会继承它，并在首次发送前保持可编辑。可编辑的新会话或未绑定
会话会在输入框中显示工作区标签，其菜单会列出最近使用与已知会话的工作区，也可以回到默认
工作区或另选一个文件夹。如果已保存的工作区文件夹被移动或删除，聊天会暂停创建会话，
并请你另选一个已存在的文件夹，而不是反复重试缺失的路径。不可用的非默认分组会在侧栏中被
标记，确认后可以移除；这会永久删除该分组内的所有会话。只有在永久删除成功之后，
会话行才会被移除、导航才会变化；删除失败则保留会话与确认框以便重试。

只有当 OpenClaw 合成的 UUID-日期兜底标题与会话 ID 相同时，才会被视为「缺失标题」，
随后用该会话的第一条用户提示替换，而不是把它持久化为会话名称。

冷启动或 Gateway 重启后 —— 在你尚未打开某个具体会话时 —— 聊天会停留在一个全新的空会话，
而不是恢复最近更新过的会话；已有会话仍会列在侧栏中。

### 文档预览

聊天右侧面板的「工作区」与「预览」页签，为 Markdown、`.docx` 和 `.pptx` 文件提供只读
预览。Markdown 预览在静态渲染模式下同样支持语法高亮、软换行、可复制的围栏代码、
面向中日韩文本的解析与 KaTeX 数学公式。预览标题栏可以把所选文件展开到整个 YYClaw 视口；
再次点击同一控件或按 Escape 即可回到面板。

限制：旧格式 `.doc` 与 `.ppt` 会交由操作系统打开而非内联预览；DOCX 的分页可能与
Microsoft Word 不同；PPTX 预览不支持动画、切换效果与媒体播放；超过 20 MB 的 Office
文件不做内联预览。

## 本地 HTML 预览

聊天右侧面板包含「工作区」、「预览」与「变更」三个页签，不提供通用浏览器、主页或
地址栏。已授权的本地 `.html` 与 `.htm` 附件、文件活动以及工作区文件默认在「预览」中打开。
文件操作允许你选择内置预览或系统应用程序，预览标题栏也可以在系统浏览器中打开当前
HTML 文件。

所有链接都不可点击。YYClaw 渲染出的链接呈现为普通文本，HTML 预览内部的链接则被移除了
样式与指针交互。HTML 预览还会阻止表单、脚本导航、重定向、hash 导航、弹窗、下载、
网络请求与设备权限。它可以渲染自包含的本地 HTML，但无法离开所选文档。

## 语音交互

与智能体对话并听取回复。语音完全通过 OpenClaw 内核原生的 Talk/TTS Gateway RPC 运行 ——
无需额外服务。

- **语音输入**使用 OpenClaw 的 **Talk 模式**。*听写*（按键说话）把语音转写进输入框，
  供你确认后再发送；*对话*模式开启持续的免手交互（聆听 → 思考 → 说话），
  具备服务端语音活动检测与打断能力。可在 **设置 → 语音** 中切换模式。
- **语音输出（TTS）**：每条助手回复都带有 🔊 播放按钮，
  **设置 → 语音 → 自动朗读** 可以自动读出最终回复。
- 首次使用时会请求麦克风权限；在 macOS 上应用会申请系统麦克风权限。

### 语音模型配置

语音模型与聊天供应商一同列在**模型**页。供应商定义在远端供应商目录可达时从远端加载，
否则回退到内置的 `resources/config/providers.json`（两者是二选一，不做合并）——
因此提供哪些能力类型（包括 `tts` / `transcription` / `realtime`）取决于该来源。

配置供应商的 API Key、模型与 Base URL；所选内容会写入 OpenClaw 配置
（`messages.tts` 与 `voice-call` 插件）。本版本支持两种内置语音运行时 —— **OpenAI**
与 **MiniMax** —— 通过供应商的 `voiceRuntimeProviderId` 选择。语音参数（音色、音频格式、
速度等）内建于这些运行时，目前不对用户开放：具备语音能力的供应商只需声明其语音模型 id，
保存账号 —— 或把它切换为默认供应商 —— 就会把这些类型桥接进同一批 OpenClaw 语音配置段。

删除某个语音供应商，或在智能体的**全局配置**中关闭语音合成，会再次从那些语音配置段中
移除相关条目；若仍有其他已配置的供应商，则将其提升为默认。

注意事项：

- OpenAI TTS 遵循 Base URL，但内核的实时转写端点固定为 `api.openai.com`
  （该处尚未应用 Base URL）。
- 实时语音需要一个与语音供应商 id 匹配的内核能力插件。
- Anthropic Claude 没有语音模型 —— 可以让 Claude 作为聊天大脑，
  搭配另一家供应商的 TTS/ASR。
- 语音严格受配置门控：当配置中未设置 `messages.tts` 或转写供应商时，对应的界面控件
  （🔊 播放按钮与 🎙️ 录音按钮）会被禁用，且桌面端会拒绝 TTS / 转写调用。
  不存在内置的默认回退。

## 多智能体管理

创建并配置多个智能体，每个都有自己的模型、启用技能与渠道绑定：

- 按智能体的**模型覆盖**（`provider/model`）；未设置覆盖的智能体继承全局默认模型。
- 按智能体的**技能白名单**（`agents.list[].skills`），在创建或编辑智能体时选择。
- **渠道绑定** —— 每张智能体卡片都有**绑定渠道**按钮，打开的弹窗可一次性把多个渠道账号
  绑定到该智能体。每个账号同一时间只由一个智能体处理。
- **全局配置** —— 默认模型选择与全局开关，例如语音合成启用开关。

## 多渠道管理

钉钉支持多账号配置，以及按需授权工作区访问。

同时配置并监控多个 AI 渠道。每个渠道独立运行，让你能为不同任务运行专门的智能体。

每个渠道支持多账号、按账号绑定智能体，并可直接在「渠道」页切换该渠道的默认账号。
每个账号都会显示实时连接状态。

对于自定义渠道账号 ID，YYClaw 强制使用与 OpenClaw 兼容的规范 ID：`[a-z0-9_-]`、小写、
最长 64 个字符、且以字母或数字开头。这可以避免路由不匹配。

YYClaw 内置了腾讯官方的个人微信渠道插件，因此你可以直接在「渠道」页通过应用内扫码流程
连接微信。其他内置渠道插件覆盖飞书 / Lark、企业微信、Discord、QQ 与 WhatsApp。

一键创建飞书应用时还会自动配置**快捷指令**机器人菜单（`/new`、`/stop`、`/reset`、
`/status`、`/compact`），用户可以通过点击机器人菜单来控制 OpenClaw 会话，无需手动输入。

## 定时任务自动化

让 AI 任务自动运行。定义触发方式与间隔，智能体便可全天候工作。

「定时任务」页允许你直接在任务表单中配置外部投递，发送账号与接收目标分别选择。
对于受支持的渠道，接收目标会自动从渠道通讯录或已知会话历史中发现，因此不再需要手工编辑
`jobs.json`。任务消息字段支持以与主聊天输入框一致的内联 `/skill` 语法插入技能
（范围限定为所选智能体），因此计划任务的提示词可以直接触发技能。

日程选择器分为**周期**与**单次**两个页签。周期提供每小时、每天、工作日、每周与自定义
原生 cron 频率，并带有内联的时间与星期控件。单次会在选定的日期（同时显示星期）与时间
执行一次。单次任务必须安排在未来的时刻，且完成后会由运行时自动移除。

升级到基于 SQLite 的运行时时，YYClaw 会在首次启动时静默地把历史 `jobs.json` /
`jobs.json.bak` 中可恢复的用户任务重建进新存储，并把原文件归档到
`~/.openclaw/cron/legacy-archive/`。`[managed-by=...]` 的内部任务交由运行时自行重建。

## 确定性工作流引擎

对于步骤明确的任务，**工作流**页会在主进程中运行一个确定性编排引擎（XState v5）。
控制流 —— 哪个节点执行、走哪个分支、循环几次 —— 是 100% 固定的；只有显式标记为
*模型*（或*智能体*）步骤的节点带有非确定性，且它受 schema 约束（`temperature=0`
加上 zod 校验与有限重试），并且可以回退到确定性路径。

每次运行都会产出逐节点的执行轨迹，把每一步标注为**确定性**或**模型**。运行以带版本的
JSON 快照持久化在 `userData/workflows/` 下，因此崩溃后可以恢复而无需重跑已完成的步骤，
实时进度则通过 `workflow:progress` 事件通道推送到界面。

引擎驱动 OpenClaw 而非相反：确定性步骤以普通的主进程函数运行，而单个受约束的模型步骤
直接与已配置的供应商通信，绕过智能体循环。

当聊天任务被自动路由到工作流时，它会以流程消息的形式**内联出现在会话中**。查询气泡会
立即显示，在服务端分解任务期间输入框复用与普通轮次相同的*思考中*指示（此时工作流卡片的
紧凑链接保持隐藏）。计划确定后，卡片链接就地出现，其浮动进度弹层自动打开；
你可以点击卡片重新打开弹层，或点击别处关闭。每个节点作为主会话的子会话运行，
而不是独立的顶层会话；完成后会有一条最终的综合回复发回会话中。

## 可扩展技能系统

- **管理技能**：在 **设置 → 技能** 中浏览、安装、卸载、管理版本和市场发布；安装技能不会自动关联智能体。
- **配置智能体**：在 **智能体 → 设置 → 技能** 中选择“使用默认方案”或“独立配置”。默认方案持续同步到继承它的智能体；独立配置只影响当前智能体，空方案表示不使用任何技能。
- **添加与调整**：通过搜索多选添加技能；“使用中”卡片支持查看说明、暂停使用和移除关联。“已暂停”区域可展开恢复使用，也可进入“选择”模式批量操作。
- **保存与取消**：操作先修改草稿，点击保存后生效；取消不改变配置，保存失败可保留草稿并重试。
- **安全卸载**：暂停保留关联，移除关联不卸载技能。有关联的技能须先从智能体或默认方案中移除，才能卸载。智能体的技能选择不会自动解除技能本身的禁用状态。

用预制技能扩展你的 AI 智能体。集成的「技能」页是本地优先的：它会扫描托管目录以及内置、
扩展与插件技能，同时排除工作区、`.agents` 和 `skills.load.extraDirs` 以避免重复版本。
技能关联和暂停在智能体设置中管理，设置侧保留技能资产管理。

「技能」页会显示每个技能的实际位置，你可以直接打开真实文件夹。安装与既有技能同名
（元数据名称或 slug 相同）的托管技能时会请求确认；确认后的替换是事务性的，
因此安装失败会恢复到先前的副本。

### 内置技能

YYClaw 预置了来自 [`anthropics/skills`](https://github.com/anthropics/skills) 的完整
文档处理技能（`pdf`、`xlsx`、`docx`、`pptx`），以及一批精选目录（GitHub、tmux、Notion、
Obsidian、Trello、天气等），它们在构建时通过独立的 `skills` CLI（`npx skills add …`，
与 OpenClaw CLI 无关）打包进来。全部会在启动时自动部署到托管技能目录
（默认 `~/.openclaw/skills`），并在首次安装时默认启用。受平台限制的技能
（例如 Apple 相关技能）只在 macOS 上部署。

部分内置搜索技能需要 API Key（例如 `TAVILY_API_KEY`、`BOCHA_API_KEY`）；
缺少密钥会以 OpenClaw 运行时配置错误的形式暴露出来。

### 服务端技能市场

根 `package.json` 中的单个 **`farmApiBaseUrl`**（仅包含协议、主机与端口，例如
`http://aiserver.example.com:9001`）驱动服务端相关功能。应用会从该 base 的
`GET /api/v1/provider-catalog` 加载 AI 供应商目录，**安装技能**侧栏（服务端来源）
则使用同一 base 的 `GET /api/v1/skill_list`（浏览）、
`GET /api/v1/skill_search?q=`（筛选）与 `GET /api/v1/skill_file/:name`（下载安装包）。
当应用设置中配置了 Farm 鉴权令牌时，会附带可选的 `Authorization: Bearer` 请求头。

安装服务端市场技能时，会先校验 ZIP 中真实的技能标识，之后才进入同名替换确认流程。

## 安全的供应商集成

TokenDance 支持浏览器授权和 API Key 配置，其可见性取决于界面语言。Anthropic 与 Google 提供预设连接参数。供应商配置支持本地或远程目录、默认模型及不同模型类型的能力槽位。

接入多家 AI 供应商，包括 OpenAI、Anthropic 与 Z.AI / GLM，凭据安全地存放在系统原生
钥匙串中。OpenAI 同时支持 API Key 与用于 Codex 订阅的浏览器 OAuth。

对于搭配 OpenAI 兼容网关使用的**自定义**供应商，你可以在
**设置 → AI 供应商 → 编辑供应商** 中为对请求头敏感的端点设置自定义 `User-Agent`。

编辑或切换供应商时，YYClaw 会保留既有的按模型能力元数据，例如
`input: ["text", "image"]`。新选择的自定义供应商模型会使用与 OpenClaw onboarding 兼容的
图像输入推断，未知模型默认为纯文本。

自定义供应商的模型行还会获得显式的 `contextWindow`，由模型家族推断（例如 `gpt-5.x`
→ 272k）。旧版本保存的行会在启动时补齐，这样 OpenClaw 就能在长会话失败于
「Context overflow」之前进行压缩。当不存在压缩配置时，YYClaw 会写入
`agents.defaults.compaction.mode = "safeguard"` 与 `reserveTokensFloor = 50000`；
你自己撰写的行或配置永不会被修改，唯一例外是缺失的 `reserveTokensFloor` 可能被补齐。

Z.AI（CN / Global）映射到 OpenClaw 内置的 `zai` 供应商（`ZAI_API_KEY`）。默认模型是
`glm-5.2`。Coding Plan 端点（`…/api/coding/paas/v4`）使用 Code Plan 预设，
普通 API 端点则用 `…/api/paas/v4`。CN 与 Global 互斥，因为它们共用同一个 OpenClaw
运行时密钥。

当兼容网关因非鉴权原因拒绝 `/models` 时，YYClaw 会在 API Key 校验期间自动回退到使用
已配置模型的轻量 `/chat/completions` 或 `/responses` 探测。

> Moonshot（Kimi）说明：YYClaw 默认保持 Kimi 联网搜索开启。配置 Moonshot 后，
> YYClaw 还会在 OpenClaw 配置中把 Kimi 联网搜索同步到中国区端点
> （`https://api.moonshot.cn/v1`）。

### Token 用量分析

「模型」页以相对滚动的 7 天与 30 天窗口（而非自然月分桶）绘制 token 用量图表，
可按模型或时间分组，并计算缓存命中率、提供逐条明细。按时间分组时，图表会保留所选窗口内
的所有天分桶；只有按模型分组会有意地截取前若干项。

Token 用量历史来自本地 OpenClaw 配置目录下的会话记录 `.jsonl` 文件，而不是解析控制台
日志。它会同时扫描已配置的智能体以及磁盘上发现的任何运行时智能体目录，并把普通的、
`.deleted.jsonl` 与 `.jsonl.reset.*` 记录都视为有效的历史来源，从中提取带
`message.usage` 的助手 / 工具用量记录。读取使用以 mtime/size 为键的增量缓存，
因此庞大的会话目录不会在主进程中反复触发全文件重扫。

## 图像生成

独立的图像生成页面位于开发者模式侧栏，端点配置与开发者设置共享；供应商和模型管理位于设置弹窗。

在开发者模式下，专门的**图像生成**页支持一个独立的 OpenAI 兼容图像生成端点
（Base URL、API Key 与模型名，例如 `gpt-image-2`），因此图像生成可以使用专用的
`/v1/images/generations` 服务，而聊天继续使用常规的 OpenAI 供应商。

聊天中的自然语言图像生成并不需要那个开发者页面。在 **设置 → AI 供应商** 中给任意
供应商账号一个 `image_generate` 模型类型，它自己的 provider key（例如
`gptimage2-gptimage/gpt-image-2`）就能直接工作 —— YYClaw 的两个内置图像插件会从
`openclaw.json` 自行探测哪些 provider key 承载了它们各自的模型家族
（`clawx-openai-image` 对应 `gpt-image-*` / `dall-e-*`，`clawx-gemini-image` 对应
`gemini-*-image`），并把这些 key 注册为别名，因此不会新建 `models.providers` 条目，
也不会复制任何 API Key。

之所以需要这样，是因为 OpenClaw 只会针对已注册进其图像生成注册表的供应商来解析图像生成
—— 单纯的 `models.providers` 条目本身永远不满足条件。已固定在
`imageGenerationModel.primary` 中的模型 id 决定了传输协议，因此请求时不做任何探测；
两个家族都不属于的模型（例如 minimax 的 `image-01` 或 Google 的 `imagen-*`）
交给 OpenClaw 自己的内置供应商处理。

两个插件的拆分是必要的，而非装饰性的：OpenAI 兼容中继会在 `/v1/images/generations` 上
拒绝非 imagen 的 Gemini 模型，而 OpenClaw 内置的 `google` 图像供应商把 Base URL 固定为
`generativelanguage.googleapis.com`，因此无法服务于中继。只要需要任一插件，YYClaw 的
预启动步骤还会设置 `agents.defaults.mediaGenerationAutoProviderFallback = false`，
这样中继无法生成的模型会以中继自身的错误失败，而不是静默地通过另一个已鉴权的供应商出图。

## OpenClaw 梦境

系统设置中的**记忆**页签管理 OpenClaw `memory-core` 的梦境机制 —— 即后台记忆整合 ——
涵盖状态、日记、维护与启用 / 停用。需要 Gateway 正在运行，
且 OpenClaw 侧已配置梦境插件。

## 自适应主题

可选择浅色模式、深色模式或跟随系统的主题。YYClaw 会自动适配你的偏好，采用暖色调配色，
所有面向用户的文案都通过 `react-i18next` 接入，覆盖 `en`、`zh`、`ja` 与 `ru`。

## 开机启动控制

在 **设置 → 通用** 中启用**开机自启动**，YYClaw 便会在登录后自动启动。

## 更新提示

YYClaw 会在启动时检查新版本。有可用更新时会显示应用内提示；只有在你选择相应操作之后，
才会开始下载与安装。

**macOS：** 若要使用应用内更新（自动更新，或你选择**安装并重启**时），请从 DMG 中把
YYClaw 复制到 **/Applications** 并从那里运行。如果直接从挂载的 DMG 或其他只读卷启动，
更新程序可能无法替换 app 包，安装步骤看起来会像什么都没做。

### 维护者须知

主进程会检查 `{CDN}/{channel}/` 下的 generic-provider 更新源，其中 channel 跟随应用
semver（stable → `latest`）。若要**强制**用户升级，请在该 channel 的 `*-mac.yml` /
`*.yml` 的**根层级**发布 `forceUpdate: true`，`electron-updater` 会把它透传给界面。
channel 目录必须与应用的 prerelease tag 匹配，否则稳定版构建会读到错误的 manifest。

## 会话维护

在启用开发者模式后的 **设置 → 高级** 中，**会话自动清理策略**表单会把
`session.maintenance`（mode / pruneAfter / maxEntries / maxDiskBytes）写入
`openclaw.json`，让 Gateway 按自己的节奏清理陈旧或超预算的会话。`mode` 默认为
`enforce`，未设置时会在启动时自动写入。`~/.openclaw/agents/*/sessions/` 下的会话记录
是追加写入的，可能达到数 GB。

## 配置存储

所有配置文件（包括 `openclaw.json` 与 `auth-profiles.json`）在开发与正式构建中均以
**明文**写入磁盘。此举旨在缓解与 OpenClaw 上游配置健康观测机制的冲突 ——
当解析结果或体积意外变化时，该机制可能生成 `.clobbered` 备份文件。
历史遗留的加密配置（`CLAWX_ENCRYPTED_v1:`）仍然可以读取。

## 本地电脑操作

在支持的 macOS 与 Windows 系统上，打开 **设置 → 设备**，主动启用“操作计算机”，并按提示授予系统权限。此入口无需开发者模式，功能默认关闭。驱动在本地运行，无需额外下载或外部配对；关闭该功能即可停止驱动。

## 🛠️ 诊断与支持

在 **设置 → 关于** 中导出本地诊断 ZIP，便于排查问题或向支持人员提供资料。诊断信息经过脱敏；原始会话记录只有在你明确选择后才会包含在导出中，文件不会自动上传。
